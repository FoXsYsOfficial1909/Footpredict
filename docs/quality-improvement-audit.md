# Почему процент не растёт и как теперь работает обучение

Аудит выполнен по актуальному репозиторию Footpredict и сохранённому ответу рабочего `GET /v1/quality` от **15 ноября 2026, 06:28 UTC / 09:28 МСК**. Исторические вероятности и метрики воспроизведены отдельно от проверки будущих матчей. Независимое улучшение качества пока **не подтверждено**.

## Какой процент виден на сайте

В верхней сводке раздела «Качество» показывается **доля правильно выбранных исходов сохранённой v1**, а не вероятность победы отдельной команды и не процент улучшения новой модели. Источник значения — `report.cohorts.v1.metrics.accuracy` в [quality-ui.js](../quality-ui.js#L191). В проверенном снимке это **2 попадания из 12, или 16,7%**, для прежних игр АПЛ и Бундеслиги.

Новый запуск обучения не меняет вероятности этих старых прогнозов и не добавляет им попадания. Значение меняется при появлении и проверке новых прогнозов именно этой серии либо при подтверждённом исправлении результата матча. Отдельный архив v2 имеет другой состав игр; сравнение его общего процента с 16,7% v1 не оценивает улучшение на одинаковых матчах.

Вероятности П1/Х/П2 отдельного матча отвечают на другой вопрос: насколько вероятен каждый исход. Вероятность победы команды не обязана расти. Log Loss и Brier оценивают достоверность всех вероятностей; меньшие значения лучше. Доля попаданий проверяет только самый вероятный исход, поэтому эти показатели могут двигаться в разные стороны.

## Что действительно работает

| Этап | Реализация и проверенные свойства |
| --- | --- |
| Получение данных | [Worker](../worker/index.mjs#L245) обращается к football-data.org и API-Football. Кэш KV проверяет возраст `fetchedAt`, обычный TTL — 300 секунд; запрос с `fresh:true` идёт к источнику. Лимиты запросов учитываются в D1. Это ограниченный по времени кэш; подтверждения, что именно старый кэш объясняет застой метрик, нет. |
| Подготовка v1 | [completedBefore / estimateStats](../worker/index.mjs#L19) берут завершённые матчи основного времени, исключают сам прогнозируемый матч и результаты с началом менее чем за четыре часа до информационного среза. Команды сопоставляются по ID, сезоны отмечаются явно. Минимум — 15 игр лиги и по две прошлые домашние/гостевые встречи нужных команд. |
| Вероятности v1 | Рабочая версия — `poisson-1.0.0`. [Настройки](../worker/index.mjs#L11) фиксированы: прошлый сезон **0,35**, полураспад **120 дней**, сглаживание **5 игр**. Домашняя и гостевая результативность считаются отдельно. [Пуассон](../worker/index.mjs#L96) суммирует П1, ничью по диагонали и П2, затем нормализует распределение. |
| Сохранение прогноза | [Снимок v1](../worker/index.mjs#L323) содержит ID и команды, время регистрации и начала игры, точные вероятности, параметры, использованные матчи и даты источников. Уникальный ключ и `ON CONFLICT DO NOTHING` защищают первоначальный прогноз от перезаписи. Совместные экспериментальные серии регистрируются минимум за сутки: [протокол](comparison.md). |
| Сверка результата | [Worker quality](../worker/quality.mjs) и [comparison](../worker/comparison.mjs) используют подтверждённый счёт, идентичность матча и время проверки. Переносы, неполные данные и расхождения видны отдельно. Метрики пересчитываются из первоначальных вероятностей; исправление результата не меняет прогноз. |
| Настоящее обучение | [LearnedPoisson.fit](../research/models.py) оценивает атаки/защиты клубов и домашнее преимущество с учётом соперников. [Ночной кандидат](../research/nightly.py) подгоняет эти веса и экспортирует Elo; настройки берёт из сохранённого раннего выбора. Веса хранятся отдельно от основной v1. |
| Подключение кандидата | [nightly-model.mjs](../worker/nightly-model.mjs) проверяет источник, срез, версию, параметры, возраст отчёта и SHA-256 весов. Файл сохраняется при регистрации нового экспериментального матча. Старые пакеты и основная v1 автоматически не заменяются. |

Обновление завершённых матчей и пересчёт сводной статистики v1 — **обновление данных**. Подгонка параметров атаки/защиты — **обучение**. Выбор полураспада, регуляризации и веса ансамбля по ранним прогнозам — **подбор настроек**. Открытие экрана качества не выполняет ни одно из этих действий.

Сглаживание v1 заметно притягивает маленькие взвешенные выборки к средним лиги. Это предусмотренное поведение, а не доказанная ошибка формулы. Оптимальность фиксированных 120/0,35/5 для каждой лиги не установлена. Свежие новости, травмы и составы пока не являются численными признаками основной модели; их наличие в карточке не означает, что они уже обучают прогноз.

## Воспроизведённое качество

Исходный опыт АПЛ использовал раннюю историю с 2015 года для оценки параметров. Настройки выбраны на сезонах **2023/24 и 2024/25**: 760 завершённых матчей, 736 общих проверенных, 24 одинаково исключённых. Поздняя оценка — **2025/26**, 380 завершённых, 369 общих проверенных и 11 одинаково исключённых из-за недостаточной прошлой истории v1. Полный охват остальных моделей также сохранён в отчёте.

| Модель на тех же 369 матчах | Попадания | Log Loss ↓ | Brier ↓ |
| --- | ---: | ---: | ---: |
| Текущая v1 | 48,51% | 1,050060 | 0,632330 |
| Сохранённый обученный кандидат | 47,43% | 1,025579 | 0,615846 |
| Базовые прошлые частоты П1/Х/П2 | 41,73% | 1,088062 | 0,659003 |

Кандидат снизил ошибки вероятностей на этих известных исторических матчах, но доля попаданий ниже v1. Изменение частоты обучения не превращает этот результат в рост попаданий.

**Brier** здесь и в рабочем Worker — средняя по матчам сумма трёх квадратов `(вероятность − индикатор исхода)²`, **без деления на три**, шкала 0–2. **Log Loss** — средний натуральный отрицательный логарифм вероятности фактического исхода с нижней границей 10⁻¹².

В [диагностическом отчёте](research/quality-audit-2026-11-15/report.md) представлены калибровка П1, Х и П2, десять фиксированных интервалов вероятностей, размеры ячеек и интервалы для фактических частот. Например, на поздней выборке v1 в среднем давала ничьей 24,53%, тогда как фактическая частота составила 27,64%. У кандидата средняя вероятность ничьей — 24,96%. Это описательное отклонение на известной истории, а не достаточное основание прибавить всем ничьим несколько процентов.

Все 1 140 исторических исходов сверены с закреплённым архивом. Вероятности v1 и базы восстановлены из прошлых результатов с допуском 1e-11; прежние метрики воспроизведены до 1e-12. Кандидат оценён по точным сохранённым последовательным прогнозам, его исторические подгонки в этом диагностическом запуске не повторялись. Хеши исходов, прогнозов, настроек и прежней сводки сохранены в [inputs.json](research/quality-audit-2026-11-15/inputs.json).

Исторический код выбирал первый точный максимум при равенстве вероятностей; будущая серия исключает равные максимумы только из знаменателя доли попаданий, сохраняя их в Brier и Log Loss. Диагностика показывает обе оценки. В проверенных исторических выборках равных максимумов нет, поэтому это различие не объясняет текущий результат.

## Что уже проверяли для улучшения

Эти результаты существовали до текущего изменения автоматизации; нового поиска лучшего варианта по уже известному позднему сезону сейчас не выполнялось.

- [Исходный протокол](research/protocol.json), [сохранённый выбор](research/selection.json) и [сводка](research/summary.json): проверены полураспады 180/365/730 дней и регуляризация 0,03/0,15 для модели с силами соперников и оцениваемым домашним преимуществом; два варианта Elo и пять весов ансамбля. Выбор по раннему Log Loss дал 365/0,03, Elo 30/80/0,9 и 75% Пуассона. Эти значения не являются новым подбором параметров сглаживания v1.
- [Проверка точности и калибровки](research/accuracy-results-2026-11-06.md): ограниченные варианты с ударами, классификаторами, Dixon–Coles и калибровкой не доказали устойчивого преимущества. Выбранная на раннем периоде температурная коррекция ухудшила поздние Log Loss и Brier, сохранив те же 47,43% попаданий. Она не повышена до основной модели.
- [Калибровка v1 на четырёх лигах](research/mixed-calibration-2026-11-12/report.md): 2 434 исходные игры, 2 202 воспроизведённых прогноза, 232 исключения. Один заранее заданный метод обучен на 1 684 ранних прогнозах. На последующих 223 и 295 общих играх обе вероятностные ошибки ухудшились относительно v1; условие внедрения не выполнено.
- [История клубов двух лиг](cross-division-learning.md) и [ограниченная поправка после перехода](transfer-policy.md) остаются исследовательскими. Исходная сотня и обе зарегистрированные серии из тех же 36 матчей не перезаписаны. Составы, травмы, погода и удары не подменяются выдуманными историческими признаками; удары в створ не называются измеренным xG.

Все эти поздние периоды уже анализировались. Дальнейшая настройка по ним создаёт новые гипотезы, но не новый независимый тест.

## Что известно по будущим матчам

В отдельном сохранённом снимке работающего API ночная совместная серия содержит **17 регистраций, 10 завершённых игр и 7 ожидающих**. Все сравниваемые модели используют одни и те же завершённые игры и подтверждённые исходы:

| Совместная будущая серия | Матчей | Попадания | Log Loss ↓ | Brier ↓ |
| --- | ---: | ---: | ---: | ---: |
| v1 | 10 | 50% | 0,974365 | 0,569945 |
| Ночной кандидат | 10 | 60% | 0,935421 | 0,545243 |
| Базовые частоты | 10 | 60% | 1,028319 | 0,617952 |

Эти значения независимо пересчитаны из сохранённых вероятностей и счетов. **Десяти игр недостаточно для вывода об устойчивом улучшении**, а попадания кандидата равны попаданиям простой базы. Все десять результатов относятся к версии от 5 ноября. У зарегистрированных версий от 14 ноября семь ожидающих игр и ноль завершённых; это не собственная будущая оценка новых весов. Исторические 369 матчей, старые 12 v1 и эти десять не объединяются в один процент.

## Что изменено для автономной работы

Новый [continuous_training.py](../research/continuous_training.py) обновляет бесплатные CSV и сравнивает отпечаток допустимой истории, настроек, кода и UTC даты среза с последним успешным обучением. При изменении выполняется реальная подгонка кандидата; при одинаковых входах результат — `unchanged`, без нового запуска оптимизатора. Дата входит в отпечаток, поскольку влияет на затухание, окно и доступность матчей. Результаты текущего и непосредственно предыдущего дня исключены из CSV-обучения: точное время публикации финального счёта неизвестно.

В ходе этой работы выполнено настоящее обновление трёх кандидатов по реальным CSV: АПЛ на истории **4 280** матчей, Чемпионшип — голевой и с прошлыми ударами — на **6 252** матчах. Это обновление весов при фиксированных настройках, а не повторный большой поиск. Полученные финальные веса ещё не проверены на собственных будущих исходах.

[Workflow](../.github/workflows/nightly-training.yml) работает **каждые шесть часов**, `43 */6 * * *` UTC, около **03:43, 09:43, 15:43 и 21:43 МСК**, независимо от открытого чата и этой рабочей среды. Расписание GitHub может задерживаться. Задачи двух лиг независимы; варианты Чемпионшипа используют одни скачанные CSV. Завершённые сезоны кэшируются; при штатном тёплом кэше обновляется только текущий CSV каждой лиги. Работают квоты и доступность GitHub и поставщика.

Проверка данных и реальное обучение теперь имеют разные журналы и даты. `latestCheck` / `checks/RUN_ID-ATTEMPT.json` содержат `trained`, `unchanged` или `failed`; `latestSuccessful` и `models/SHA256.json` сохраняют последний успешный кандидат. Неизменный вход не делает старые веса новыми. Ошибка не стирает прошлый успешный результат; следующий цикл пробует снова. Подробности и сценарий отказа описаны в [training.md](training.md).

Это автономная работа весь день и всю неделю по расписанию. Непрерывной загрузки процессора и гарантии запуска точно в заданную минуту нет. Ускорение обновления данных не означает доказанного роста точности. Основная v1 сохранена; новая модель продолжает сравниваться параллельно. Прежние веса остаются в адресуемом по хешу архиве, замороженные прогнозы защищены от перезаписи.

Проверка реализации: **253 Python-теста и 161 Node-тест прошли**. Отдельная браузерная проверка подтвердила отображение на настольном и мобильном экранах, неизменные входы и сбой с сохранением последнего успешного результата. Пять тестов диагностического модуля и его команда воспроизведения выполнены; сам модуль использует стандартную библиотеку. Это проверка работы кода и отчётности, а не подтверждение будущей точности.

## Готовые файлы и запуск

Реализация уже находится в репозитории: [проверка и условное обучение](../research/continuous_training.py), [публикация журнала](../scripts/publish_training.py), [workflow](../.github/workflows/nightly-training.yml), [отображение дат и статусов](../training-ui.js), [диагностика качества](../research/quality_diagnostic.py) и [готовый отчёт с закреплёнными входами](research/quality-audit-2026-11-15/report.md). Менять Worker или вводить секреты для этого обучения не требуется.

1. Обновите приложение из `main` репозитория `FoXsYsOfficial1909/Footpredict`. Для нового клона: `git clone https://github.com/FoXsYsOfficial1909/Footpredict.git`, затем `cd Footpredict`.
2. В GitHub → Actions убедитесь, что workflow **Nightly candidate training** включён. После публикации соответствующих изменений в `main` он выполняет проверку цепочки; вручную доступен **Run workflow**. Для плановой публикации используется стандартный `GITHUB_TOKEN` с `contents:write` внутри задания.
3. Откройте [отчёт обучения на сайте](https://foxsysofficial1909.github.io/Footpredict/#qualityNightly), затем блок «Ночное обучение кандидатов». Прямая ссылка открывает инструменты владельца, не добавляя пунктов в обычное меню. Смотрите отдельно дату проверки источников, дату обучения и размер оценённой выборки. Для расследования сбоя откройте ссылку на запуск GitHub, сохраняя дату прежнего успешного кандидата.
4. Для повторения в облачном рабочем окружении выполните команды ниже. `scripts/setup.sh` требует Python, Node и стандартный образ проекта; в другом локальном окружении можно создать собственное виртуальное окружение и установить `requirements-research.txt`. Диагностика сохранённых прогнозов использует только стандартную библиотеку и сеть не запрашивает.

```bash
bash scripts/setup.sh
source /workspace/.venvs/footpredict/bin/activate

python -m research.quality_diagnostic --output /tmp/footpredict-quality-audit

OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 python -m research.continuous_training \
  --league PL --data-dir data/nightly --output artifacts/nightly

OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 python -m research.continuous_training \
  --league ELC --data-dir data/championship --output artifacts/championship \
  --shots-output artifacts/championship-shots

python -m unittest discover -s tests
node --test tests/*.test.mjs
python scripts/build_site.py --check
```

Не запускайте условное обучение с каталогом вывода внутри `docs/research`: этот путь намеренно защищён, чтобы не менять зарегистрированные исследования. Приведённые локальные команды не публикуют новые веса в основной Worker.

Для остановки автоматических попыток отключите workflow в GitHub Actions. Для возврата к прежней автоматизации верните предыдущую версию workflow через обычное изменение в `main`; архивы не удаляются, основная v1 продолжает работать. Автоматического повышения кандидата или переписывания истории нет.
