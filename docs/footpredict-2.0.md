# FootPredict 2.0

## Откуда берётся качество

Карточка матча показывает три вероятности П1, Х и П2. Процент попаданий в сводке показывает долю совпадений одного самого вероятного исхода с итогом. В прежнем журнале было **2 попадания из 12**. На 18 ноября 2026 в совместной серии АПЛ завершились **10 из 20** сохранённых игр. Пуассон угадал 5, ночной ансамбль и частоты лиги угадали по 6. Дополнительные тренировки изменяют вероятности кандидата для последующих матчей. Старые попадания определяют сохранённые прогнозы и фактические счета.

Страница использует расписание и результаты football-data.org. API-Football обслуживает ручной режим и доступные дополнительные сведения. Автоматическая сверка и запись предматчевых прогнозов АПЛ выполняются в Cloudflare. Ключи поставщиков остаются в Secrets. KV хранит ответы с ограниченным сроком жизни. D1 хранит версии, неизменяемые снимки прогнозов, результаты и очередь. Предматчевые проверки берут команды по идентификаторам поставщика. Снимки CSV для обучения сопоставляются с расписанием по проверенным алиасам клубов. [Worker](../worker/index.mjs) · [Автоматические задачи](automation.md) · [Обучающие данные](neural-learning.md)

[Основная модель Пуассона](model-card.md) оценивает голы дома и в гостях с отдельными средними лиги. Она использует фиксированный вес прошлого сезона 0,35, полураспад 120 дней и сглаживание пятью играми. При расчёте учитываются только завершённые матчи с доступным счётом. Минимум 15 игр лиги и по две игры дома и на выезде ограничивает расчёт на слишком маленьких выборках. Ничьи получаются суммированием вероятностей равных счетов. Сетка счетов 0–20 нормируется. Округление на основных экранах даёт 100,0% в сумме, а исходная точность сохраняется в журнале.

Проверка теперь отклоняет противоречивые дубликаты матчей, невозможные счета и совпадающие идентификаторы команд. Точный дубликат учитывается один раз. Старые записи читаются через прежний API, время создания и итог сохраняются отдельно. История загружается одним запросом D1 на страницу. Worker передаёт время получения исходного ответа, когда оно известно. Для старого кеша интерфейс показывает момент получения календаря браузером и отмечает отсутствие времени источника. При сбое ручного обновления остаётся последнее загруженное расписание. [Журнал и сверка](../worker/index.mjs) · [Сводки качества](../worker/quality.mjs)

## Воспроизведённые сравнения

Основная метрика — Log Loss. Она сильнее штрафует уверенные ошибки. Brier — средняя сумма `Σ(p_k − y_k)²` по трём исходам на матч, шкала 0–2. Меньшие значения обеих ошибок лучше. Равные максимумы участвуют в Log Loss и Brier. Долю попаданий считают среди матчей с единственным максимумом и указывают число равных максимумов.

| АПЛ, сезон 2025/26 | Основной Пуассон | 369 | 48,51% | 1,050060 | 0,632330 |
| | Обученный ансамбль | 369 | 47,43% | 1,025579 | 0,615846 |
| | Частоты лиги | 369 | 41,73% | 1,088062 | 0,659003 |
| АПЛ, сохранённая совместная серия на 18 ноября | Основной Пуассон | 10 | 50% | 0,974365 | 0,569945 |

| | Частоты лиги | 10 | 60% | 1,028319 | 0,617952 |

История с 2015/16 служила для оценки весов, сезоны 2023/24 и 2024/25 для выбора настроек. В них 760 игр, 736 общих и 24 без допустимого прогноза Пуассона. В использованном при разработке сезоне 2025/26 было 380 завершённых, 369 общих и 11 без допустимого прогноза Пуассона. Каждая строка использует прошлые матчи с запасом времени. Данные, исключения и калибровка П1/Х/П2 входят в повторяемый аудит. [Исходная проверка](research/quality-audit-2026-11-15/report.md) · [Метрики всех моделей](research/quality-audit-2026-11-15/report.json)

В сезоне 2025/26 прогноз Пуассона в среднем выделял победе хозяев 44,05% при факте 41,73%, ничьей 24,53% при факте 27,64%, победе гостей 31,42% при факте 30,62%. У ансамбля средние 42,83%, 24,96% и 32,21%. Отчёт содержит размеры диапазонов, фактические частоты и интервалы. Историческая проверка показывает меньшие ошибки ансамбля и **не подтверждает устойчивое преимущество на новых матчах**. Десяти сохранённых игр пока мало для такого вывода.

Сравнения Elo, обученного Пуассона с силами соперников, логистической регрессии, ансамбля, калибровки и Dixon–Coles используют одинаковые игры внутри каждого эксперимента. Нейросеть также воспроизведена. В поздней исторической проверке 1 484 матчей её средний по трём лигам Log Loss составил 1,036891 против 1,058054 у прежней модели. В мониторинге Чемпионшипа на 180 матчах Log Loss вырос с 1,056778 до 1,069975. Она продолжает проверяться отдельно в АПЛ. Градиентный бустинг не включён в эту версию. Составы, травмы, погода, xG и угловые не используются основной моделью. Для xG и других собранных признаков существуют отдельные исследования с описанием источников. ### Условие смены модели

Зафиксированы **190 матчей АПЛ** сезона 2026/27 в турах 14–32. Идентификаторы football-data.org от 560672 до 560861. Отсчёт записей начинается 19 ноября 2026 в 00:00 UTC. Итог берётся из наблюдений по состоянию на **3 мая 2027, 07:50 МСК**. Результаты просмотренных ранее игр в решение не входят. Прогнозы кандидата и двух сравнений должны быть записаны вместе минимум за сутки до матча. Каждый прогноз содержит точные веса и хеши. Допуск относится к процедуре обновления ансамбля с зафиксированным рецептом в АПЛ.

Для допуска нужны подтверждённые результаты минимум 90% фиксированного списка и не менее 18 туров. Кандидат должен снизить средний Log Loss минимум на 0,005 против Пуассона и частот, а также сохранить или снизить Brier против обоих. Верхняя граница разницы Log Loss должна быть ниже нуля в обеих парных проверках. Для границы используется 2 000 выборок туров с возвращением и уровень 97,5% для каждого из двух сравнений. Интервалы приближённые, поскольку игры между турами могут быть зависимыми. Пропущенный, перенесённый или непроверенный матч остаётся в знаменателе охвата. Worker фиксирует решение один раз. [Условие и расчёт](../worker/model-release.mjs)

При допуске ансамбль используется для новых записей совместной серии АПЛ с проверенным артефактом того же рецепта. Прочие лиги, ручной калькулятор и предматчевые расчёты без проверенного сохранённого прогноза используют Пуассон. Глобальный переключатель в Worker применяется при регистрации новых записей. У записанной игры сохраняются модель, вероятность и время исходного прогноза. Независимая проверка нейросети продолжается отдельно. [Регистрация и сверка](../worker/comparison.mjs)

## Интерфейс и охват

- На главной карточки показывают календарь выбранной лиги, три вероятности, время их формирования, состояние матча и счёт. Изначально открыт календарь АПЛ. Кнопка «Все соревнования» загружает список доступных лиг. Поиск и основные фильтры находятся над матчами, дополнительные фильтры раскрываются по запросу. Избранное и тема хранятся в браузере.
- Подробности показывают использованные средние голы, краткую форму команд и доступные предыдущие игры. Для сохранённого прогноза доступны версия, исходное время и ссылка на входные данные совместной серии. Голы в завершённых матчах берутся из подтверждённых результатов или помеченного календаря.
- Уверенность оценивается по размеру исходных выборок и исторической надёжности того же наиболее вероятного исхода в соответствующем диапазоне. Используется минимум 25 более ранних сопоставимых игровых дней и интервал Wilson. При нехватке доказательств виден статус «Недостаточно данных». Фильтр уверенности меняет только список карточек.
- «Аналитика ИИ» показывает одни и те же игры для сравниваемых моделей, фильтры по периоду и лиге, калибровку П1/Х/П2 и динамику средней ошибки. Серийные сводки вычисляются по полным журналам, даже когда список архивных карточек ограничен. Диагностика проверяет расхождения прогноза и факта по игровым дням. Причины расхождений требуют отдельных экспериментов.
- Охват в календаре показывает число прогнозов среди всех предстоящих матчей загруженного окна. В эксперименте охват относится к полному фиксированному списку. Автоматические совместные прогнозы пока относятся к АПЛ. Список других лиг и глубина текущего архива зависят от провайдера и тарифа.

## Запуск и откат

1. Сайт раскрывается на существующем GitHub Pages. Резервный адрес обслуживает тот же комплект в Worker по `/app/`. Для локального просмотра запустите `python3 -m http.server 8000 --bind 127.0.0.1` из корня проекта. [Основной адрес](https://foxsysofficial1909.github.io/Footpredict/) · [Резервный адрес](https://footpredict-api.wzjp5747md.workers.dev/app/)
2. После обновления кода проверьте `python3 scripts/build_site.py --check`, Python и Node с командами ниже. Откройте матч, затем «История» и «Аналитика ИИ». Убедитесь, что видна дата записи и доступны исходные данные.
3. Для публикации Worker запустите `python3 -m scripts.deploy_worker --backup-dir /tmp/footpredict-worker-pre-2.0`. Скрипт сохраняет исходный код и состояние конфигурации и выводит список модулей. После проверки запустите его с `--apply` и **новой** папкой резервной копии. Право доступа используйте из уже настроенного окружения. Связанные базы, Secrets, KV и триггеры наследуются.
4. Для возврата к Пуассону на будущих записях добавьте обычную переменную Worker `FOOTPREDICT_PUBLIC_MODEL=poisson`. Для отката кода Worker выполните `python3 -m scripts.deploy_worker --rollback /путь/к/резервной-копии --backup-dir /tmp/footpredict-before-rollback --apply`. Для отката сайта используйте `git revert` коммита выпуска. Контрольная точка до 2.0 — `cb765f348724b60234230353924e54b537df941b`. [Скрипт выпуска и восстановления](../scripts/deploy_worker.py)

```bash
python3 -m pip install -r requirements-research.txt
OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 python3 -m unittest discover -s tests
node --test tests/*.test.mjs
python3 scripts/build_site.py --check
OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 python3 -m scripts.benchmark_neural_update
python3 -m research.quality_diagnostic --output /tmp/footpredict-quality
```
