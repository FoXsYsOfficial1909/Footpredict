# Обучение поправки на доступность игроков

Протокол `availability-residual-1` связывает исходные снимки FPL с отдельным обучением вероятностей П1/Х/П2. Основные вероятности приложения v1 не меняются. Базой первого эксперимента служит уже сохраняемая экспериментальная v2 `ensemble-v2-experimental-0.1`; преимущество над ней само по себе не является разрешением заменить v1.

## Что сохраняется и извлекается

С `research-0.9.0` официальный FPL кеш содержит игровые минуты текущего сезона и позицию каждого зарегистрированного игрока. В карточку записываются исходные статусы, даты, состав реестра и минуты на момент получения. Это прокси роли игрока внутри реестра FPL, а не полная оценка качества замены. Запись с объявленным уходом в другой клуб исключается.

`research.features.feature_row` теперь проверяет `playerAvailability` и `reportedLineups`. Проверяются команды, UTC время игры, время получения и публикации, уникальность игроков и окно доступности источника. Неизвестные минуты остаются пустыми. Давние и недатированные сообщения не превращаются в подтверждённые потери. Исторические снимки остаются исходными: сегодняшние минуты к ним не присоединяются.

Числовые признаки первого эксперимента:

- Доля минут игроков со свежим сообщением о травме, дисквалификации или иной недоступности.
- Доля минут игроков со свежей отметкой «под вопросом».
- Доля минут игроков с неясными, давними или недатированными отметками.

Каждый признак — разность долей гостей и хозяев. Обучается три коэффициента регуляризованной поправки к логитам `[delta, 0, -delta]`. Настройки, пороги и признаки зарегистрированы в [плане](research/availability-plan-2026-11-11.json). Подбор вариантов по текущим результатам не выполняется.

## Отдельные временные окна

Для дневной поправки выбирается один последний пригодный снимок на матч, полученный от 24 до 168 часов перед началом. Повторные карточки не увеличивают размер выборки. Результаты обучения допускаются только от игр, начавшихся минимум четыре часа назад, при статусе FINISHED, совпадении команд/времени и счёте основного времени.

Стартовые 11 ESPN проверяются и извлекаются отдельно только в позднем окне до 90 минут перед игрой. Их идентификаторы и позиции сохраняются для будущего исследования состава; в текущую дневную поправку они не входят. У 24-часового прогноза не может появиться информация, опубликованная за час до игры.

## Когда начинается обучение

Нужны минимум 60 пригодных завершённых матчей, все три вида исхода и меняющиеся значения признаков. Этот порог разрешает первую попытку обучения, не обещает полезности. Если данных недостаточно, отчёт имеет статус `collecting`, веса отсутствуют, прогнозы поправки не создаются.

При достаточных данных выполняется хронологическая проверка: для каждого среза используются только более ранние завершённые игры. Это ретроспективный расчёт с текущими подтверждёнными счетами, он подписан отдельно. Дополнительно при готовой модели новые будущие пары v2/поправка сохраняются за 24–48 часов до начала. Первая запись с точными весами и исходным снимком неизменна; последующие переобучения её не заменяют.

Отдельный сигнал пользы допускается после 60 завершённых будущих пар минимум за десять разных дней: верхняя граница 95% интервала разности ошибок должна быть ниже нуля одновременно для Brier и Log Loss. Перевыборка блоками по UTC дню сохраняет зависимость одновременных матчей. Даже при прохождении условия автоматического включения в v1 нет; сначала нужно оценить результат и сравнение с основной моделью.

## Автоматическая работа

[GitHub Actions](../.github/workflows/availability-experiment.yml) ежедневно около 05:13 МСК восстанавливает исходные наблюдения, дочитывает архив, проверяет результаты, обучает при достаточной выборке и публикует отчёт в ветке `availability-reports`. Ручной запуск доступен владельцу через Actions. Посещение приложения обучение не запускает.

`GET /v1/research/training?after=CURSOR` читает максимум четыре неизменных снимка. Порядок курсора соответствует вставке, поэтому запоздалое сохранение более раннего среза не теряется. Ответ содержит точную исходную JSON-строку и SHA-256. Запрос не обращается к поставщикам, не запускает ИИ и не изменяет прогнозы. Это фиксированный архивный маршрут, а не доступ к произвольному SQL. Счета сезонов читаются общим кешированным запросом.

На отдельной ветке сохраняются исходные снимки, курсор, точные веса, неизменные будущие прогнозы и история запусков. При ошибке предыдущие успешные данные сохраняются, а последняя попытка явно получает статус `failed`. Дополнительных ключей и платного API для обучения не требуется.

Состояние видно в «Инструменты владельца → Качество → Обучение поправки на доступность игроков». Публичный интерфейс сохраняет три вкладки. Счётчики различают повторные срезы, уникальные матчи, сведения FPL и пригодные записи с минутами.

Локальная проверка:

```bash
OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 python -m unittest tests.test_player_features tests.test_availability_experiment
python -m scripts.publish_availability restore --state-dir data/availability
python -m research.availability_experiment --state-dir data/availability --output artifacts/availability
```
