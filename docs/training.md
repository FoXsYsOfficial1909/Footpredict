# Ночное обучение кандидатов

С 15 ноября 2026 workflow `Nightly candidate training` проверяет данные **каждые шесть часов**, ежедневно: `43 */6 * * *` UTC, около **03:43, 09:43, 15:43 и 21:43 МСК**. Он также запускается вручную через workflow_dispatch и при изменении кода/настроек обучения в main. Расписание GitHub может задерживаться. Работа не зависит от открытого чата или облачной рабочей среды. Cloudflare продолжает свой сбор и расчёт действующих версий.

`research.continuous_training` сначала обновляет публичные CSV, проверяет целостность и сравнивает отпечаток входов с последним успешным обучением. Отпечаток включает допустимые прошлые результаты, статистику ударов для соответствующего кандидата, UTC дату среза, настройки и код. Изменения будущих и ещё недопустимых результатов не вызывают преждевременное обучение. При изменениях запускается настоящая подгонка весов с прежними настройками; при одинаковых входах оптимизатор не запускается. Новая дата среза также считается изменением: она влияет на временные веса, окно обучения и доступность результатов.

Проверка данных записывается отдельно в `latestCheck` и `checks/RUN_ID-ATTEMPT.json` каждой ветки отчётов. Статусы — `trained`, `unchanged`, `failed`. Время проверки не подменяет время последнего обучения и не делает старые веса новыми. Неизменный вход не создаёт новую успешную попытку обучения. Ошибка источника, подгонки или сохранения артефакта сохраняет последний успешный результат; следующий плановый цикл повторяет проверку. Ошибки до старта проверки, например при установке зависимостей, видны в GitHub, а интерфейс предупреждает об устаревшей проверке.

АПЛ и Чемпионшип работают отдельными задачами. Для Чемпионшипа голевой вариант и вариант с ударами используют одни и те же обновлённые CSV; повторных запросов ради ударов нет. Каждая публикация остаётся в своей ветке. Локальный бесконечный процесс и постоянно работающий сервер обучения не нужны. Это автономный цикл весь день и всю неделю, а не непрерывная загрузка CPU; рост качества от частоты запусков не заявляется.

`research.nightly` загружает результаты АПЛ с 2015 года. Завершённые сезоны берутся из кэша, текущий обновляется каждый раз. Незавершённый архив прошлого сезона повторно скачивается и должен содержать 380 матчей. Проверяются даты, команды, счёт, исход и дубликаты. Для каждого источника сохранены URL и SHA-256. В артефакте есть также сжатый снимок фактически использованных строк: дата, сезон, команды и голы.

Настройки остаются из `docs/research/selection.json`: модель атаки/защиты, Elo и вес ансамбля. Полный перебор сетки каждую ночь не повторяется. Модель Пуассона использует прежнее трёхлетнее окно, Elo — доступную прошлую историю. Прогон использует один поток и переиспользует предыдущие параметры при последовательных исторических обучениях.

Для CSV известны даты игр, но не точное время публикации результата. Поэтому окончательное обучение исключает текущий и непосредственно предыдущий календарный день UTC. Срез данных и последняя использованная игра указаны отдельно. Финальные веса кандидата не считаются проверенными на матчах, которые вошли в его обучение.

Исторический мониторинг проходит по последним примерно 120 доступным матчам, сохраняя целиком граничный календарный день. Перед каждым прогнозом обучение использует только более ранние данные, с тем же суточным ограждением. В таблицу попадают одинаковые матчи для кандидата, v1 и базы; пропуски v1 исключены у всех. Требуется минимум 60 общих игр. Это мониторинг процедуры с уже выбранными настройками, а не новый независимый тест и не подбор параметров по последним результатам.

У кандидата отдельная версия, контрольная сумма весов, хеш данных, настроек и кода. Артефакты model.json/model.mjs, отчёт, исторические прогнозы и снимок данных хранятся в GitHub Actions 90 дней. Ночной workflow не загружает код в Worker, не меняет текущую v2 и не пересчитывает зарегистрированные совместные прогнозы.

Краткие отчёты публикуются в отдельную ветку training-reports: latest.json и неизменяемые runs/RUN_ID-ATTEMPT.json. При неудаче обновляется последняя попытка, а последний успешный отчёт сохраняется. Главная ветка и приложение не перепубликуются ежедневными бот-коммитами. Для публикации используется стандартный GITHUB_TOKEN с contents:write; секреты поставщиков и токен владельца не нужны.

Во вкладке «Качество» есть раскрывающийся блок «Ночное обучение кандидатов». Он читает публичный краткий отчёт только после открытия, показывает время фактического запуска, историю данных, метрики процедуры и ссылки на артефакты. Устаревший или неудачный отчёт не показывается как свежий успех.

Цепочка проверена на [запуске по расписанию 5 ноября 2026 года](https://github.com/FoXsYsOfficial1909/Footpredict/actions/runs/41948734057): 4270 матчей истории, 110 общих матчей исторической проверки, около 2,9 секунды на загрузку/подготовку данных, обучение и проверку. Задача GitHub целиком заняла 22 секунды. Контрольные суммы скачанного артефакта модели, снимка данных, настроек и кода сверены; метрики повторно рассчитаны из сохранённых прогнозов. Отчёт проверен на опубликованном сайте в настольном и мобильном браузере. Это подтверждение работы цепочки; метрики исторической процедуры не оценивают будущую точность новых весов.

Новая версия не повышается до основной автоматически. Для оценки новых финальных весов нужна отдельная будущая серия, зарегистрированная до матчей. Травмы, составы и новости пока не входят в числовые признаки этого кандидата.

С 5 ноября 2026 года эта серия подключена отдельно: [протокол `nightly-live-1`](candidate-comparison.md). Проверенные веса публикуются также в `training-reports/models/SHA256.json`. Worker сохраняет точный файл в пакете будущего матча и сравнивает кандидата с v1, прежней v2 и базой. Первая регистрация и версия для уже записанного матча остаются неизменными.

Локальный запуск:

```bash
python -m research.nightly --data-dir data/nightly --output artifacts/nightly
```

Для того же цикла проверки и условного обучения, который выполняется в GitHub:

```bash
python -m research.continuous_training --league PL \
  --data-dir data/nightly --output artifacts/nightly
python -m research.continuous_training --league ELC \
  --data-dir data/championship --output artifacts/championship \
  --shots-output artifacts/championship-shots
```

### Установка и контроль работы

1. Готовый workflow находится в `.github/workflows/nightly-training.yml`. После публикации в `main` запускается проверка всей цепочки. В GitHub → Actions → Nightly candidate training доступны журнал и ручной `Run workflow`.
2. Для расписания достаточно включённого GitHub Actions и стандартного `GITHUB_TOKEN` с правом `contents:write` внутри задания. Новые API-ключи или VPS не нужны. Используются стандартные Linux runners, две ограниченные по времени задачи, кэш завершённых сезонов и прежние бесплатные CSV. Действуют квоты и доступность GitHub/источника.
3. В разделе сайта «Качество» → «Ночное обучение кандидатов» отдельно проверяйте дату получения данных и дату реального обучения. При отсутствии изменений веса и дата обучения остаются прежними. Метрики исторического мониторинга не являются новой независимой проверкой.
4. Весам соответствуют неизменяемые `models/SHA256.json`; отчёты и проверки хранятся в `training-reports`, `championship-training-reports`, `championship-shots-training-reports`. Полные входы и прогнозы доступны в артефактах GitHub Actions 90 дней. Существующий Worker использует проверенные веса АПЛ только при регистрации новых экспериментальных матчей; прежние прогнозы не меняются.
5. Чтобы остановить автоматические попытки, отключите workflow в Actions. Основная v1 продолжит работу. Для возврата к прежней автоматизации верните предыдущую версию workflow в `main`; сохранённые модели и исходные пакеты не удаляются. Основной прогноз автоматически не повышается до кандидата.

Для воспроизведения можно передать --as-of YYYY-MM-DD и --offline при наличии всех CSV. Значения времени расчёта и полного цикла с загрузкой различаются в отчёте; время подготовки виртуальной машины GitHub в них не входит.

Проверка интерфейса кэшированных ИИ-сведений читает только сохранённую карточку, без сбора новостей и новых вызовов ИИ:

```bash
FOOTPREDICT_TEST_URL=https://foxsysofficial1909.github.io/Footpredict/ \
FOOTPREDICT_RESEARCH_ID=560632 python tests/browser_availability.py
```

Проверка различает новый и повторно использованный выбор ИИ, проверяет наличие исходного времени выбора, цитаты и пояснения о сверке с текущим источником.
