# Ночное обучение кандидатов

Workflow `Nightly candidate training` запускается ежедневно в 00:23 UTC / 03:23 МСК, вручную через workflow_dispatch и при изменении кода/настроек обучения в main. Последний триггер проверяет цепочку перед будущим ночным запуском. Расписание GitHub может задерживаться. Обучение работает без открытой рабочей среды. Cloudflare продолжает сбор и расчёт действующих версий.

`research.nightly` загружает результаты АПЛ с 2015 года. Завершённые сезоны берутся из кэша, текущий обновляется каждый раз. Незавершённый архив прошлого сезона повторно скачивается и должен содержать 380 матчей. Проверяются даты, команды, счёт, исход и дубликаты. Для каждого источника сохранены URL и SHA-256. В артефакте есть также сжатый снимок фактически использованных строк: дата, сезон, команды и голы.

Настройки остаются из `docs/research/selection.json`: модель атаки/защиты, Elo и вес ансамбля. Полный перебор сетки каждую ночь не повторяется. Модель Пуассона использует прежнее трёхлетнее окно, Elo — доступную прошлую историю. Прогон использует один поток и переиспользует предыдущие параметры при последовательных исторических обучениях.

Для CSV известны даты игр, но не точное время публикации результата. Поэтому окончательное обучение исключает текущий и непосредственно предыдущий календарный день UTC. Срез данных и последняя использованная игра указаны отдельно. Финальные веса кандидата не считаются проверенными на матчах, которые вошли в его обучение.

Исторический мониторинг проходит по последним примерно 120 доступным матчам, сохраняя целиком граничный календарный день. Перед каждым прогнозом обучение использует только более ранние данные, с тем же суточным ограждением. В таблицу попадают одинаковые матчи для кандидата, v1 и базы; пропуски v1 исключены у всех. Требуется минимум 60 общих игр. Это мониторинг процедуры с уже выбранными настройками, а не новый независимый тест и не подбор параметров по последним результатам.

У кандидата отдельная версия, контрольная сумма весов, хеш данных, настроек и кода. Артефакты model.json/model.mjs, отчёт, исторические прогнозы и снимок данных хранятся в GitHub Actions 90 дней. Ночной workflow не загружает код в Worker, не меняет текущую v2 и не пересчитывает зарегистрированные совместные прогнозы.

Краткие отчёты публикуются в отдельную ветку training-reports: latest.json и неизменяемые runs/RUN_ID-ATTEMPT.json. При неудаче обновляется последняя попытка, а последний успешный отчёт сохраняется. Главная ветка и приложение не перепубликуются ежедневными бот-коммитами. Для публикации используется стандартный GITHUB_TOKEN с contents:write; секреты поставщиков и токен владельца не нужны.

Во вкладке «Качество» есть раскрывающийся блок «Ночное обучение кандидатов». Он читает публичный краткий отчёт только после открытия, показывает время фактического запуска, историю данных, метрики процедуры и ссылки на артефакты. Устаревший или неудачный отчёт не показывается как свежий успех.

Новая версия не повышается до основной автоматически. Для оценки новых финальных весов нужна отдельная будущая серия, зарегистрированная до матчей. Травмы, составы и новости пока не входят в числовые признаки этого кандидата.

Локальный запуск:

```bash
python -m research.nightly --data-dir data/nightly --output artifacts/nightly
```

Для воспроизведения можно передать --as-of YYYY-MM-DD и --offline при наличии всех CSV. Значения времени расчёта и полного цикла с загрузкой различаются в отчёте; время подготовки виртуальной машины GitHub в них не входит.
