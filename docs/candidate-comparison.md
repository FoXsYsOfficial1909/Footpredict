# Ночной кандидат на будущих матчах

Протокол `nightly-live-1` начинается после публикации 5 ноября 2026 года. Для будущих матчей АПЛ в пределах семи дней он фиксирует одной записью четыре прогноза П1 / Х / П2: основную v1, прежнюю зафиксированную v2, частоты лиги из v1 и последнего проверенного ночного кандидата. До начала должно оставаться минимум 24 часа. Уже сохранённые записи прежних серий не дополняются кандидатом задним числом.

Кандидат выбирается при первой успешной регистрации матча. Ночное обучение использует фиксированные настройки из сохранённого эксперимента: окно Пуассона 1095 дней, half-life 365, ridge 0,03; Elo k=30, преимущество хозяев 80, вес ничьей 0,9; вес Пуассона 0,75. Хеш настроек закреплён в протоколе. Изменение настроек требует нового протокола, чтобы результаты разных процедур не смешивались.

Worker читает `latestSuccessful` из публичной ветки `training-reports` фиксированного репозитория. При неудаче очередного обучения допускается предыдущий успешный кандидат, пока ему не больше 36 часов. Проверяются версия, время запуска, происхождение, даты среза, число обучающих матчей и параметры. Текущий и непосредственно предыдущий день UTC исключены из обучения. Устаревший, будущий, неполный или повреждённый кандидат откладывает задачу без записи частичного сравнения.

Файл весов публикуется в `models/SHA256.json`. Его точные канонические байты имеют SHA-256 из отчёта обучения; имя файла не зависит от пользовательского ввода. Worker строит URL сам, не следует перенаправлениям и не отправляет секреты. Проверенный исходный JSON, его хеш, отчёт обучения, commit, номер запуска и времена получения сохраняются в доказательном пакете каждого матча. Это позволяет воспроизвести прогноз после следующего обучения и после истечения срока хранения артефакта Actions.

Все четыре прогноза рассчитываются и записываются одновременно. Сохраняются входные результаты v1, её параметры, предматчевые источники, данные кандидата и заметки о пропусках. Перед записью заново проверяются статус, команды и время игры; SQL отдельно закрывает запись за сутки до начала. Первая запись не перезаписывается повторным запуском или следующей версией кандидата.

В новых матчах могут использоваться разные ночные версии. Поэтому общий столбец кандидата оценивает **процедуру ночного обновления**, а не один набор весов. JSON и интерфейс показывают также отдельные версии: число зарегистрированных игр, ожидающие результаты и метрики всех четырёх моделей на матчах именно этой версии. Историческая проверка ночного обучения показывается отдельно и не становится результатом будущей серии.

Автоматическая очередь сохраняет не более одного нового сравнения кандидата за проход, начиная с ближайшего времени начала среди задач, готовых к запуску. После задержки повторная попытка срочного матча имеет приоритет перед более старыми задачами с поздним началом. Используются существующие бюджеты football-data.org; лимиты не увеличиваются. Недоступность архива обучения не останавливает прежнее сравнение, новости и остальные виды задач. Чтение отчёта в браузере не запускает регистрацию, сбор или обучение.

Результат принимается минимум через четыре часа после начала при совпадении команд, времени и подтверждённом счёте основного времени. Переносы, отмены, неподтверждённые результаты и неполные записи исключают матч у всех четырёх моделей. Исправления провайдера добавляют наблюдение, не меняя вероятности. Ежедневный отчёт использует только записи и результаты, известные к своему срезу.

У Brier и Log Loss общий набор матчей. Равные максимумы остаются в этих ошибках, но исключаются из доли совпадений конкретной модели. До результатов показываются прочерки. Малая выборка не доказывает преимущество. Новости, травмы и составы пока не входят в вероятности; автоматического повышения кандидата до основной модели нет.

API только для чтения:

- `GET /v1/candidate-comparison` — общие метрики, версии и последние 100 матчей; сводки охватывают всю серию.
- `GET /v1/candidate-comparison/ID/evidence` — исходный пакет с точными весами и входами.
- `GET /v1/quality` — серия в поле `nightly`, отдельно от прежнего `prospective`.
- `GET /v1/automation/status` — счётчик `nightlyComparison` и состояние очереди.
- `GET /v1/model-candidate` — проверка загрузки текущего файла весов и его контрольной суммы. Читает только публичный архив обучения, не создаёт прогноз и не обращается к поставщикам матчей; при недоступном или неподтверждённом файле возвращает ошибку.

В приложении серия находится во вкладке «Качество», блок «Ночной кандидат · будущие матчи».

Для независимого воспроизведения скачай «Исходный расчёт» матча и выполни из репозитория:

```bash
python -m scripts.verify_candidate footpredict-candidate-comparison-ID.json
```

Команда использует только стандартную библиотеку Python, сохранённые входы и точный файл кандидата. Параметры прежней v2 берутся из зафиксированного `worker/model-v2-data.json`, его версия и срез проверяются, а хеш включается в результат. Четыре распределения пересчитываются отдельно от кода Worker с допуском 10⁻¹⁰; проверяются хеш кандидата и временные ограждения. Команда не обращается к сети и не меняет данные. Она проверяет содержимое пакета; факт предматчевой регистрации подтверждается серверной записью, из которой пакет скачан.
