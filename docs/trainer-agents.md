# Автономные тренеры Footpredict

Это четыре ограниченные программы на Python, запускаемые GitHub Actions без открытого чата и без постоянно работающей облачной среды. Они не обращаются к платной языковой модели, не переписывают свой код и не повышают экспериментальную сеть до основной автоматически.

| Роль | Что делает | Что сохраняет |
| --- | --- | --- |
| Данные | Обновляет бесплатные CSV АПЛ, Чемпионшипа и League One; проверяет результаты, дубликаты и принадлежность клубов | Снимок строк и SHA-256 источников |
| Тренер | При изменении допустимых данных или кода обучает сеть по одному зафиксированному рецепту | Веса, нормализацию, параметры, время реальной подгонки и отпечаток входов |
| Контролёр | Проверяет процедуру на последних 120 матчах каждой лиги с более ранним обучением | Исторические вероятности, Log Loss, Brier и калибровку; это не независимый тест |
| Наблюдатель | Сохраняет прогнозы на будущие матчи АПЛ и позднее добавляет счёт из существующего проверенного журнала Worker | Неизменяемый первоначальный прогноз и отдельное наблюдение результата |

Workflow: [Autonomous trainer agents](https://github.com/FoXsYsOfficial1909/Footpredict/actions/workflows/trainer-agents.yml). Расписание — `53 */6 * * *` UTC, около **03:53, 09:53, 15:53 и 21:53 МСК**. Запуск возможен также вручную и после изменения соответствующего кода в `main`. GitHub может задержать расписание. Работа доступна весь день, но CPU не занят непрерывно: без новых входов повторная подгонка не нужна.

## Границы цикла

- Максимум две подгонки: более ранняя сеть для исторического контроля и окончательная сеть для будущих прогнозов. Каждая — не более 200 итераций, один вычислительный поток, один seed, один рецепт, 963 параметра. Если достигнут лимит, отчёт прямо указывает отсутствие подтверждённой сходимости.
- Без изменений входов — **ноль подгонок**. Дата проверки обновляется, время обучения и файл весов сохраняются. Простая смена даты сама по себе не запускает нейротренера; это отличается от прежнего ночного кандидата с временным окном.
- При прогретом кэше обновляются три CSV текущих сезонов; закрытые сезоны повторно не скачиваются. Первый запуск получает до 31 сезонного файла. Неполный закрытый сезон проверяется повторной загрузкой. Действуют ограничения GitHub и доступность источника.
- Максимум пять новых прогнозов за цикл, только АПЛ, от 24 часов до семи дней до игры. Время регистрации проверяется **после** расчёта. Уже сохранённый прогноз следующая сеть не переписывает. Это ограничение скорости записи, а не отбор матчей по ожидаемой точности.
- Исходы читаются через `GET /v1/quality`, без новых запросов к футбольным поставщикам из этой задачи. Результат принимается только при подтверждённом `FINISHED`, совпадении команд/времени и спустя минимум четыре часа после начала. Перенос или отозванный результат помечается для проверки; такой матч не считается успешным попаданием.
- Составы, травмы, новости, погода и xG не подменяются оценками при отсутствии подходящей истории. Признаки этой сети описаны в [отчёте](neural-learning.md).

В `registered`, `pending`, `settled`, `review`, `unavailable` отдельно видны все записанные матчи. Метрики сравнивают кандидата, прежнюю вероятность и исторические частоты на одних и тех же завершённых играх. Пустая выборка имеет `null`, а не выдуманный процент. Серия пересекается с уже существующими экспериментами АПЛ; нельзя складывать эти матчи как независимые проверки.

## Хранение и восстановление

Отдельная ветка [`trainer-agent-reports`](https://github.com/FoXsYsOfficial1909/Footpredict/tree/trainer-agent-reports) содержит:

- `latest.json`: последнюю попытку и последний успешный цикл;
- `reports/RUN_ID-ATTEMPT.json`: неизменяемый отчёт каждого запуска;
- `models/SHA256.json`, `datasets/SHA256.json.gz`, `sources/SHA256.json`: точные веса, фактические входные строки и снимок источника будущих матчей;
- `forecasts/FIXTURE_ID.json`: первую вероятность, время регистрации и игры, версию и хеш модели, признаки, базовые вероятности и происхождение входов;
- `state/`: контрольную точку для следующего запуска, включая отдельные результаты матчей и проверенный кэш признаков.

Публикация отказывается заменять или удалять первый прогноз. Ошибка источника, обучения, проверки или сохранения артефакта оставляет предыдущую опубликованную модель. Git хранит прежние контрольные точки; полные артефакты запуска доступны 14 дней, чтобы ограничить расход хранилища Actions. Необходимые для воспроизведения веса, входные строки и первые прогнозы также остаются в отдельной ветке. Пропущенный запуск продолжает следующий плановый цикл, без зависимости от этой рабочей среды.

## Установка и контроль

1. Готовые файлы — `.github/workflows/trainer-agents.yml`, `research/trainer_agents.py`, модули `research/neural_*.py` и `scripts/publish_trainer_agents.py`. После попадания в `main` workflow запускается сам. Нужны включённые GitHub Actions и стандартное право `contents:write` внутри задания. Новые API-ключи, подписка на LLM и VPS не требуются.
2. На сайте откройте **Инструменты владельца → Качество → Ночное обучение кандидатов**. Под прежним отчётом появился компактный статус автотренеров. Основные три вкладки не изменились.
3. В Actions доступны статус, артефакт и `Run workflow`. Проверяйте отдельно `checkedAt` и `trainedAt`: свежая проверка не означает новые веса. Ошибка подготовки runner может произойти до записи отчёта; интерфейс предупреждает, если проверка старше 12 часов.
4. Чтобы приостановить цикл, отключите **Autonomous trainer agents** в Actions. Прежний Worker и основная модель продолжат работать. Для возврата программы используйте предыдущий commit `main`; ветку журналов не переписывайте и не удаляйте. Отдельная исследовательская сеть пока не подключена к основным прогнозам, поэтому откат основной модели для неё не требуется.

Локально, из корня репозитория:

```bash
python -m pip install -r requirements-research.txt
python -m scripts.publish_trainer_agents restore --state-dir data/trainer-agents
OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 python -m research.trainer_agents \
  --state-dir data/trainer-agents --output artifacts/trainer-agents
```

Последняя команда действительно получает данные, подгоняет веса при изменениях и регистрирует будущие прогнозы в локальном состоянии. Она сама не публикует их в GitHub. Публикацию и её неизменяемые архивы выполняет workflow.
