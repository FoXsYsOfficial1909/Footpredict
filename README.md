# Footpredict

Футбольная аналитика и прогнозы. Интерфейс на русском, статический сайт без сборки.

Основное меню: **Матчи · История · Качество**. Разделы открываются вкладками, сохраняя выбранный матч и введённые значения. Инструменты владельца доступны отдельно. Старые ссылки продолжают работать; [подробности навигации](docs/navigation.md).

Каждые шесть часов GitHub Actions проверяет данные и при изменении доступной истории, настроек, кода или даты среза обучает отдельных кандидатов. Работа продолжается без открытого чата; неизменные входы не запускают повторную подгонку. Текущая модель автоматически не заменяется. Во вкладке «Качество» отдельно видны проверка данных и фактическое обучение: [устройство обучения и воспроизведение](docs/training.md).

- Приложение: https://foxsysofficial1909.github.io/Footpredict/
- API: https://footpredict-api.wzjp5747md.workers.dev
- Backend: Cloudflare Worker, D1, KV и Workers AI. Ключи поставщиков хранятся на сервере.

## Запуск

Нужны Python 3.12+ и Node.js 24+ для проверок. Самому интерфейсу достаточно HTTP-сервера:

```bash
python3 -m http.server 8000 --bind 127.0.0.1
```

Точный локальный origin разрешён в API. Другие порты и посторонние origins не разрешены.

Для исследовательских инструментов и браузерной проверки в облачной среде:

```bash
bash scripts/setup.sh
source /workspace/.venvs/footpredict/bin/activate
```

Скрипт сохраняет настройки прокси и проверку TLS. Импорт публичного сертификата среды в Chromium необязателен для старта; перед HTTPS-проверкой браузера он должен успешно выполниться. Chromium и certutil предоставляет образ среды.

## Автоматическая работа

Сбор и отчёты выполняются в Cloudflare при закрытом приложении и отключённой рабочей среде. Очередь, время следующей попытки и результаты хранятся в D1. После прерывания аренда задачи истекает, и её может продолжить следующий запуск. Ошибка одного источника не блокирует остальные виды задач.

- Рабочий запуск: в минуты 07 и 37 каждого часа UTC. За запуск обрабатывается ограниченная часть очереди.
- Существующий триггер проверки результатов сохранён: `17 */2 * * *`.
- Ежедневный отчёт: `50 4 * * *`, то есть 07:50 МСК. При пропуске формируется при следующем запуске с фактическим временем и отметкой задержки.
- Примерный интервал проверки клубных лент — 2 часа. Карточки матчей обновляются по очереди с учётом близости матча и квот.
- Лимиты приложения: 12 сборов карточек и 4 вызова ИИ в сутки. Дневной сброс — 00:00 UTC / 03:00 МСК. Бюджеты поставщиков и KV также действуют.

В приложении доступны состояние сбора, ежедневный отчёт с JSON-экспортом и отдельная история v2. Отправка сообщений в мессенджеры не настроена.

## Модели и данные

[Аудит качества и автономного обучения](docs/quality-improvement-audit.md) объясняет, какой процент показывает сайт, воспроизводит прежние метрики и калибровку и отдельно проверяет новые будущие матчи. Готовые файлы, условия сравнения и инструкции запуска включены; независимое улучшение точности пока не подтверждено.

[Проверка зависимости низких счетов](docs/dixon-coles-learning.md) оценила одну поправку Dixon–Coles по 1 900 ранним прогнозам. Поздние ошибки выросли, поэтому поправка не включена. Интерфейс 1.11 теперь показывает основную модель, кандидата и базу на общей будущей выборке; исходные архивные проценты сохранены отдельно.

Основная модель — `poisson-1.0.0`. Её сохранённая история остаётся отдельной. Экспериментальная v2 сочетает обучаемую модель атаки/защиты и Elo. Вероятности v2 фиксируются минимум за 24 часа до матча; итоги оцениваются по этим вероятностям с отдельными наблюдениями результатов. Переносы и изменения идентичности матча требуют проверки.

Новости, травмы и составы **пока не используются в вероятностях**. Состояние игроков бесплатно загружается из официального структурированного API Fantasy Premier League; опубликованные стартовые 11 — из ESPN ближе к началу игры. Карточка загружается сразу при выборе матча, без кнопки сбора и вызова ИИ. Сообщения имеют источник и дату; отсутствие сообщения не означает отсутствие травмы. Официальное подтверждение клуба и полный календарь всех турниров не гарантируются. Подробности: [бесплатные сведения об игроках](docs/player-context.md).

Разбор дополняют короткие сообщения клубов и прессы о доступности игроков. Официальные новостные страницы проверяются отдельной очередью примерно раз в 12 часов, постепенно для всех текущих клубов. Цитаты доступны и без ИИ; ИИ-разбор выбирает готовые фрагменты по номеру, используя ограниченную JSON Schema. Он не генерирует исходную цитату или URL. Статьи с советами FPL/fantasy по-прежнему исключены из отбора цитат; официальный структурированный API подключён отдельно. Обзор источников, ограничения и способы проверки описаны в [сводках о доступности](docs/availability.md).

Историческая проверка: [карточка модели](docs/model-card.md). Проверка исходной серии: [аудит результатов](docs/results-audit.md). Архитектура, API и восстановление: [автоматическая работа](docs/automation.md).

[Новая серия из 100 будущих матчей](docs/research/hundred-2026-11-11/README.md) зафиксирована 11 ноября 2026 до начала игр. Прогнозы, CSV и исходные данные неизменны; автоматическая сверка результатов работает каждые шесть часов. Серия видна во вкладке «История» и оценивается отдельно от прежних архивов.

[Проверка отдельных моделей четырёх лиг](docs/research/league-strength-2026-11-14/report.md) выполнена на 518 исторических матчах с последовательным обучением по прошлым результатам. Общие средние ошибки снизились, но кандидат ухудшил результаты Чемпионшипа, а интервалы общего отличия пересекают ноль. Основная модель сохранена; параметры, все прогнозы и причины решения доступны в отчёте.

[Обучение Чемпионшипа](docs/championship-learning.md) теперь использует отдельный бесплатный архив 12 сезонов, 6 252 матча. Настройки выбраны на ранних сезонах; более поздняя проверка не доказала устойчивого улучшения, поэтому кандидат остаётся экспериментальным. Ежедневное задание обновляет его веса без нового перебора параметров и сохраняет их в отдельной ветке, не заменяя архив АПЛ и основные прогнозы.

[Вариант с прошлыми ударами в створ](docs/championship-shots.md) использует допустимую статистику 6 250 игр и сохраняет результаты двух неполных матчей. Вероятностные ошибки ниже, чем у того же кандидата без ударов, в трёх исторических периодах; в текущем сезоне v1 пока лучше. Оба кандидата обновляются одним ночным заданием по тем же CSV, с отдельными архивами и без дополнительных обращений к поставщику.

[Будущая проверка на 36 матчах Чемпионшипа](docs/research/elc-future-2026-11-14/README.md) зафиксирована 14 ноября в 20:59 МСК. Сохраняются точные вероятности кандидата с ударами и исходные v1 из прежней сотни; первые игры — 21 ноября. Результаты сравниваются отдельно тем же расписанием, без дополнительных запросов к поставщику и без переключения основной модели.

[История клубов между АПЛ и Чемпионшипом](docs/cross-division-learning.md) проверена отдельным опытом на 10 532 исходных матчах. Общие параметры клубов используют прошлые игры обоих дивизионов, сохраняя отдельные средние и домашнее преимущество лиг. В двух поздних периодах ошибки ниже прежнего кандидата, но устойчивое преимущество над v1 не доказано; зафиксированные серии и основная модель сохранены.

[История League One](docs/league-one-learning.md) добавляет 3 470 проверенных матчей третьего дивизиона и по 122 прошлые игры Bolton и Lincoln. Один фиксированный вариант трёх лиг проверен на тех же 1 753 прогнозах Чемпионшипа. Ошибки двух поздних периодов ниже двухдивизионного кандидата, но текущая v1 лучше, а ранний период ухудшился. Вариант остаётся исследовательским; исходные прогнозы не заменяются.

[Ограниченная поправка для клубов после смены лиги](docs/transfer-policy.md) обучена на ранних прогнозах и применяется только при малой истории E1 и достаточной истории E0. На уже изученных поздних матчах ошибки вероятностей ниже v1, но независимого подтверждения нет. Новая регистрация сохраняет те же 36 будущих матчей и меняет лишь шесть прогнозов; их результаты считаются отдельно. Исходные серии не перезаписываются.

Статусы FPL, игровые минуты и сохранённые составы теперь читаются [экспериментальным обучением поправки](docs/availability-learning.md). Оно запускается ежедневно отдельно от посещений сайта. Для первой попытки нужны 60 пригодных завершённых матчей; старые карточки без минут остаются неполными. Основные вероятности v1 не меняются, объявленные составы не попадают в прогноз за сутки.

Раздел [«Качество прогнозов»](https://foxsysofficial1909.github.io/Footpredict/#qualityDashboard) показывает размер выборки, долю совпадений, Brier и Log Loss, сравнение на общих матчах и разбор ошибок. Исторический эксперимент доступен отдельным режимом. Открытие раздела читает только сохранённые данные. Определения, исключения и API: [оценка качества](docs/quality.md).

С 4 ноября 2026 года отдельная очередь регистрирует v1, v2 и простую базу одновременно минимум за сутки до будущей игры. Это новая перспективная серия, отдельная от старых архивов. Условия, сохранность входов и API описаны в [протоколе сравнения](docs/comparison.md).

С 5 ноября 2026 года ночной кандидат подключён к [отдельной будущей серии из четырёх моделей](docs/candidate-comparison.md). Точная версия и веса сохраняются до матча; результат сравнивается с одновременно рассчитанными v1, прежней v2 и базой. Общее сравнение процедуры и разбор по версиям доступны во вкладке «Качество».

## Проверки

```bash
python3 -m unittest discover -s tests
node --test tests/*.test.mjs
```

Node-тесты очереди исполняют настоящий SQLite через `node:sqlite` и проверяют восстановление после прерывания, исключение одновременного выполнения, временные ограничения, неизменность вероятностей и независимость задач при ошибке.

Браузерная проверка требует запущенного локального сервера, Playwright, Chromium и доверия к публичному CA среды:

```bash
python3 scripts/trust_browser_ca.py
python3 tests/browser_smoke.py
python3 tests/browser_quality.py
python3 tests/browser_availability.py
python3 tests/browser_player_context.py
python3 tests/browser_source_translation.py
python3 tests/browser_availability_learning.py
python3 tests/browser_hundred.py
python3 tests/browser_navigation.py
python3 tests/browser_training.py
```

Она обращается к действующему API и может запустить ограниченный сбор карточки. Общие прогнозы v1 не создаёт. Не запускайте её часто без изменений: действуют квоты поставщиков.

`browser_quality.py` проверяет новый экран, фильтры, экспорт, обработку отказа и мобильную вёрстку. Он читает только серверный архив и не запускает сбор или сверку.

`browser_availability.py` проверяет сведения о доступности, исключение FPL и экспорт на последней сохранённой карточке. Сетевой вызов формы направляется на stored-only API, поэтому новые карточки и вызовы ИИ не расходуются.

`browser_player_context.py` проверяет автоматическую загрузку, пустые и недоступные источники, подписи составов, защиту от позднего ответа другого матча и мобильную вёрстку на локальных фикстурах. Новых карточек, вызовов ИИ или прогнозов не создаёт.

`browser_navigation.py` проверяет три публичные вкладки, отдельный вход в инструменты владельца, кнопки браузера, клавиатуру, старые ссылки и мобильный экран. Он не запускает подробный сбор или создание прогнозов.

`browser_training.py` проверяет ленивую загрузку отчёта обучения, экспорт, сохранение последнего успешного результата при ошибке и мобильный экран.

## Публикация Worker

Текущий интерфейс также доступен на [постоянном адресе Worker](https://footpredict-api.wzjp5747md.workers.dev/app/). Это резервная публикация, независимая от GitHub Pages. `scripts/build_site.py` упаковывает только публичные HTML/CSS/JS, на которые ссылается страница, в `worker/site-assets.mjs`. Развёртывание автоматически обновляет пакет; `python3 scripts/build_site.py --check` проверяет его соответствие исходникам. База и секреты в пакет не входят. Статический интерфейс и API работают на одном адресе, существующая GitHub Pages CORS-настройка сохраняется.

Используются уже настроенные `CLOUDFLARE_ACCOUNT_ID` и `CLOUDFLARE_API_TOKEN`. Значения секретов не копируются в репозиторий или интерфейс.

```bash
python3 -m scripts.deploy_worker --backup-dir /workspace/scratch/footpredict-deployment-review
# После проверки: тот же вызов с новым каталогом и --apply.
python3 -m scripts.configure_automation --backup /workspace/scratch/footpredict-schedules-review.json
# Для применения расписаний: новый путь резервной копии и --apply.
```

Загрузка сначала сохраняет резервную копию, проверяет отсутствие параллельных изменений, затем сверяет опубликованные исходники побайтно и проверяет сохранность настроек. Добавление расписаний сохраняет существующие триггеры. Обычный запуск среды ничего не переопубликовывает.
